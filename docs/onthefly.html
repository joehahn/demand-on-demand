Forecasts by week, quarter or year

Every forecast on this site starts the same way: the AI agent writes one SQL query that picks the order lines for the request, and names the time grain (week, month, quarter or year) and how far ahead. Fixed code does the rest:

  • The AI decides what to forecast: which order lines, which measure, and how to label each series.
  • Fixed code decides how: it adds the lines up by week or month, keeps complete periods only, fills empty periods with 0, picks and tests the model (the baseline is the same period last year; weekly models refit every 4 weeks), and draws the results. Quarters and years are forecast by month: "next quarter" is the next three months (the data rarely ends on a quarter's last day, so a calendar quarter ahead would include months already known).
  • The AI's SQL is tested: on 34 test requests, 3 runs each, its order lines are added up and compared with an answer key built by hand-checked fixed code.

The AI writes its SQL following three rules for this warehouse's traps, found by testing AI-written SQL against a reference, and the company's business definitions (what "minis" or "whiskey" means).

The three rules
## Rules for this warehouse (follow them exactly)
1. Products: never filter order lines on item_no alone. Products were renumbered over the years; select the product's
   whole family: il.item_no IN (SELECT item_no FROM sales.item WHERE family_item_no IN (...)).
2. A brand (every size and flavor): match ALL the brand's words anywhere in the family's current name, not as a
   prefix (barrel picks are named e.g. 'BP CROWN ROYAL ...'): il.item_no IN (SELECT i.item_no FROM sales.item i JOIN
   sales.item h ON h.item_no = i.family_item_no WHERE h.item_desc ILIKE '%CROWN%' AND h.item_desc ILIKE '%ROYAL%').
3. Categories: never use invoice_line.category_code (codes were reassigned in 2016). Use today's category of the
   product: il.item_no IN (SELECT item_no FROM sales.item WHERE category_current IN (...)).

the AI's query and assumptions
SELECT
  l.ordered_on AS day,
  l.store_no AS store_no,
  l.item_no AS item_no,
  'total' AS series,
  l.sales_bottles AS value
FROM sales.invoice_line l
JOIN sales.store s ON s.store_no = l.store_no
WHERE l.item_no IN (
  SELECT i.item_no
  FROM sales.item i
  JOIN sales.item h ON h.item_no = i.family_item_no
  WHERE h.item_desc ILIKE '%TITOS%'
    AND h.item_desc ILIKE '%HANDMADE%'
    AND h.bottle_volume_ml = 50
)
AND s.city = 'DES MOINES'
AND l.ordered_on >= '2016-01-01'
  • Minis means 50 ml bottles, matched by the product family's current bottle_volume_ml, including the 4-pack mini item which is also 50 ml per bottle
  • Des Moines means stores whose city is recorded as DES MOINES, not West Des Moines
  • Product family selected by matching both 'TITOS' and 'HANDMADE' in the family's current item description, covering all renumbered item numbers over time
  • History included from 2016-01-01 onward as available
  • Measure is bottles sold (sales_bottles), which already accounts for mini packs as individual bottles
