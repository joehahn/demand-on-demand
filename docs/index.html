demand-on-demand

Ask for a demand forecast in plain English. Get a tested forecast and dashboard in under a minute.

A business user types a question like "monthly forecast of Tito's minis in Des Moines for the next 5 months". One Claude agent with read-only tools turns the words into SQL that picks the right orders from a company-style Postgres warehouse of 26 million Iowa liquor orders (2016 to 2026). Fixed Python code then adds them up, tunes and tests the models against the simplest honest benchmark, the same period last year, and publishes a dashboard that says how far to trust the answer. By week, month, quarter or year.

How it works

  • The AI decides what to forecast; code decides how. The agent resolves products, places, measures and horizons with read-only tools, and writes one SQL query that picks the order lines: which lines, which measure, how to label each series. It knows the warehouse from a data dictionary of every table and column, read from the database, plus three rules for its traps and the company's business definitions. It never touches the sums, the train/test split, the metrics or the charts. Those are fixed code, the same for every request.
  • Honest accuracy. Every forecast is backtested on the last 24 months, which no choice ever saw. Model settings are tuned on the two years before that, and "same month last year" is always a candidate: a model is used only as far as it beats it.
  • Clean data, fixed once. The public data has real problems: duplicated export rows, recoded categories, renumbered products, inconsistent spellings. They are documented on the data exploration page and fixed once, in the warehouse, as shown on the data fixes page. No forecast has to know they existed.
  • Least privilege. The agent's database login can only read the clean tables. Credentials stay in the Python process and never appear in a prompt.

Example forecasts

4 requests typed in plain English, each run once, shown as they came out, the misses included.

“Monthly forecast of Tito's minis in Des Moines for the next 5 months”

Tito's minis in Des Moines are forecast at about 34,800 bottles over the next 5 months, up 21% from the same months last year. This forecast is 8% more accurate than simply repeating last year's outcome.

Backtest: 8% more accurate than repeating last year (0.92). 18 s, $0.02.
“What revenue should we expect from Fireball in Linn County next quarter?”

Next quarter's forecast for Fireball in Linn County totals about $576,000, essentially flat versus the same months last year. This forecast is 11% more accurate than simply repeating last year's outcome.

Backtest: 11% more accurate than repeating last year (0.89). 64 s, $0.04.
“How many bottles of cream liqueur will Iowa stores order for the holidays?”

Cream liqueurs in Iowa are forecast at about 243,000 bottles over September through December, down 8% from the same months last year. This forecast is 25% more accurate than simply repeating last year's outcome.

Backtest: 25% more accurate than repeating last year (0.75). 25 s, $0.02.
“show me weekly forecast of Cream liqueur bottles sold across all of iowa, twelve weeks out”

Forecast calls for about 172,000 bottles over the coming weeks, up 4% from the same weeks last year. This forecast is about as accurate as simply repeating last year's outcome.

Backtest: about as accurate as repeating last year (1.00). 28 s, $0.01.

How good is it?

Forecast accuracy. On 30 forecasts sampled from the warehouse (products, categories, vendors; counties and statewide; bottles, dollars and liters; 3 to 12 months ahead), the chosen model beat "same month last year" on 20, with a median error 9% lower than that baseline (median monthly error 16.2% vs 16.0%). Retail demand here is very regular year to year, so last year is a hard baseline to beat, and on the rest it was not beaten. Full benchmark.

Agent accuracy. The agent's SQL is tested against an answer key: 34 requests (brands, categories, minis, cities, counties, a 207-store chain, weeks, quarters, a year, and requests it should decline), each with correct monthly totals built by hand-checked fixed code. Over 102 runs, its order lines added up to the key in every month in 101, and 101 were right in every respect (grain and horizon too, or correctly declined). Every number in the dashboard summaries is checked against the models' results. Test report.

How it got there. An earlier version had the AI fill in a request form and fixed code write the SQL (slot filling). Comparing AI-written SQL with it month by month found three warehouse traps (renumbered products, recoded categories, brand names with extra words); three short rules fixed them. The answer key then showed every remaining miss was a business definition ("minis" by size, whiskey without whiskey liqueur), fixed with a short glossary. Weekly, quarterly and yearly examples.
