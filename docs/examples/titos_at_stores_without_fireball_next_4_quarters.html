Why it was read this way
  • Tito's = the whole brand family (all sizes, mini packs, PET, etc.), matched on the family's current description containing TITOS.
  • Fireball = the whole brand family (all flavors, sizes, gift packs), matched on the family's current description containing FIREBALL; a store is excluded if it has ever ordered any Fireball item since 2016-01-01.
  • Measure is sales_dollars (revenue), one row per order line, no aggregation (fixed code sums it).
  • Quarters are calendar quarters: Q3 2026 in progress (Jul-Sep, actuals through Aug 31 plus forecast for Sep), then Q4 2026, Q1 2027, Q2 2027.
  • History included from 2016-01-01 through the latest available data (2026-08-31).

What the agent did

How the AI agent (Claude) turned the request into what “Read as” shows at the top. It writes the SQL that selects the sales records (which products, which stores, which measure) and names the time grain. Fixed code then checks that the SQL can only read data, never change it; sums the selected records into monthly totals for each series; picks and tests the model; and generates this page.

The agent's toolbox. The AI agent (Claude Sonnet 5) does text-to-SQL. To turn words like “cream liqueur” or “Des Moines” into the warehouse's own codes it has 3 tools: search the names of products, categories, vendors, stores and places; run a small test query; and, in a live session, ask the requester one clarifying question when a request is ambiguous. None of them can change the data. It then writes one SQL query that selects the sales records to forecast (instructions, tools).

The agent's rules and business definitions

Part of its instructions for every request: three rules for this warehouse's traps, and the company's definitions of common business words.

## Rules for this warehouse (follow them exactly)
1. Products: never filter order lines on item_no alone. Products were renumbered over the years; select the product's
   whole family: il.item_no IN (SELECT item_no FROM sales.item WHERE family_item_no IN (...)).
2. A brand (every size and flavor): match ALL the brand's words anywhere in the family's current name, not as a
   prefix (barrel picks are named e.g. 'BP CROWN ROYAL ...'): il.item_no IN (SELECT i.item_no FROM sales.item i JOIN
   sales.item h ON h.item_no = i.family_item_no WHERE h.item_desc ILIKE '%CROWN%' AND h.item_desc ILIKE '%ROYAL%').
3. Categories: never use invoice_line.category_code (codes were reassigned in 2016). Use today's category of the
   product: il.item_no IN (SELECT item_no FROM sales.item WHERE category_current IN (...)).

## Business definitions (the company's dictionary; follow them unless the user says otherwise)
- A brand (e.g. Hawkeye Vodka, Crown Royal) means every product of that brand: all sizes, flavors, packs and barrel
  picks.
- A spirit type (whiskey, vodka, American vodka, rum, ...) means its own categories, flavored ones included (American
  vodka includes American Flavored Vodka), but not liqueurs or ready-to-drink cocktails made from it: whiskey does not
  include Whiskey Liqueur (e.g. Fireball). Select the categories by name, never by a typed list of codes, e.g. whiskey:
  il.item_no IN (SELECT i.item_no FROM sales.item i JOIN sales.category c ON c.category_code = i.category_current
  WHERE c.category_name ILIKE '%WHISK%' AND c.category_name NOT ILIKE '%LIQUEUR%').
- Sizes go by bottle size, not by words in the product name: minis are 50 ml, pints 375 ml, fifths 750 ml, liters
  1000 ml, handles 1750 ml. Use the product family's size: h.bottle_volume_ml with h the family's current item.
- A vendor's products (e.g. all Diageo products) means the order lines that vendor sold (l.vendor_no), not the
  products it owns today: brands change hands.
- A period named by an event or season means through its end: "for the holidays" is through December 31.

The SQL as run

Written by the AI, checked to be one read-only SELECT, and run under a read-only database login, inside fixed code's own sums (by month, store and product). It selected 212 sales records (Jan 2016 through Aug 2026).

SELECT
  il.ordered_on AS day,
  il.store_no   AS store_no,
  il.item_no    AS item_no,
  'total'       AS series,
  il.sales_dollars AS value
FROM sales.invoice_line il
WHERE il.item_no IN (
  SELECT i.item_no FROM sales.item i JOIN sales.item h ON h.item_no = i.family_item_no
  WHERE h.item_desc ILIKE '%TITOS%'
)
AND il.store_no NOT IN (
  SELECT DISTINCT il2.store_no FROM sales.invoice_line il2
  WHERE il2.item_no IN (
    SELECT i.item_no FROM sales.item i JOIN sales.item h ON h.item_no = i.family_item_no
    WHERE h.item_desc ILIKE '%FIREBALL%'
  )
)
AND il.ordered_on >= '2016-01-01'
