How the model was chosen

Model: the average of the top 3 of 96 configurations, blended 50% with 50% same month last year (explained below); 8% more accurate than repeating last year over a 20-origin backtest on Sep 2024 to Aug 2026, months the model never trained on.

How this forecast is made. 96 model configurations were scored on Sep 2022 to Aug 2024, before the test window; a selection error below 1 beats repeating the same month last year. The forecast uses the average of the top 3:

  1. Ridge regression predicting monthly bottles directly from the values 1, 2, 3 and 12 months back, regularization strength 10, trained on this series only (all history). Selection error 0.990 vs the baseline.
  2. LightGBM (gradient-boosted trees, 7 leaves) predicting monthly bottles directly from the last 12 months, trained on this series plus the same product in the 15 busiest counties (all history). Selection error 1.000 vs the baseline.
  3. Ridge regression predicting monthly bottles directly from the values 1, 2, 3 and 12 months back, regularization strength 1, trained on this series only (all history). Selection error 1.034 vs the baseline.

Each month's forecast is then 50% this model average plus 50% of what sold in the same month last year. That mix scored 0.871 on the model-selection window, the best of every combination tried (1 or 3 models, 0% to 100% model), vs 0.895 for the best model alone and 0.928 for the 3-model average alone. The pieces make different mistakes, so the mix partly cancels them.

Aggregation SQL (generated by the harness, run under the read-only role):

SELECT date_trunc('month', l.ordered_on)::date AS month,
       'total' AS series,
       l.store_no,
       sum(l.sales_bottles) AS value
FROM sales.invoice_line l
JOIN sales.item i USING (item_no)
JOIN sales.store s USING (store_no)
WHERE l.item_no = ANY(ARRAY['38185', '38194', '38180', '938180'])
  AND s.city = ANY(ARRAY['DES MOINES'])
  AND l.ordered_on >= '2016-01-01'
GROUP BY 1, 2, 3
ORDER BY 1, 2, 3
